## Differences found in the initial inspection (corrected in follow-up)

- **Spike Slime M/L AI:** Java chooses Tackle for rolls below 30, subject to
  repetition restrictions; Rust chose Lick on that branch. Java
  also changes Lick repetition at A17; Rust did not. See
  `SpikeSlime_M.java:84` and `SpikeSlime_L.java:131`.
- **Acid Slime AI:** M/L have distinct ascension-dependent thresholds, history
  restrictions, and extra RNG decisions in fallback branches. Rust simplified
  these to shared 40/70 thresholds and deterministic fallbacks. Small Acid
  Slime sets its next move directly in `takeTurn`; Rust rerolled each action.
- **Demon Form ordering:** Java grants Strength in `atStartOfTurnPostDraw`,
  after the queued normal draw (`GameActionManager.java:267`). Rust applied it
  before drawing (`src/player.rs:start_turn`). Current cards do not have
  draw-triggered damage, but the ordering differed.
- **Round-end hook ordering:** Java runs all monster end-turn hooks, then
  player round-end hooks, then monster round-end hooks
  (`MonsterGroup.java:316`). Rust interleaved each monster's end-turn and
  round-end hooks, then ticked the player.

## Follow-up implementation and checks

- Acid M/L now use their Java ascension thresholds, repeat limits, and fallback
  coin types/probabilities. Spike M/L use 30% Tackle before repeat restrictions,
  with the A17 Lick restriction. Small Acid Slime alternates directly after its
  initial move; Slime Boss cycles directly without extra AI rolls.
- Spike L preserves the discarded parent's queued roll after its children
  spawn. Acid L and Slime Boss do not consume that extra roll.
- Demon Form has a separate post-draw hook. Ordinary additional card draws do
  not trigger it. End-of-round phases now follow MonsterGroup's hook ordering.
- Seven AI regression tests cover every primary roll (0–99), ascension
  boundaries, repeat limits, both fallback outcomes, coin choice, and RNG call
  counts. One additional power test checks Demon Form's hook and extra draws.
  Split tests also check child/parent AI roll counts.
- These are source-derived regression expectations, not Java execution tests.
  Round-end ordering is checked by source inspection; future cross-creature
  effects will require further interaction tests.
- Interface remains v3 (178 observations / 61 actions); existing v3 checkpoints
  still load, but changed combat behavior and seed sequences require reevaluation.

## Remaining differences and next validation work

Java shows UNKNOWN for a split and STRONG_DEBUFF for boss Goop; Rust uses
distinct Split and generic Debuff features. Exact RNG sequence parity remains
unverified, including the RNG primitives, stream seeding and constructor HP
rolls. Player Ritual also remains unsupported.

Record the original JAR build and checksum when available. Capture controlled original-game combat
traces and compare state after each action, explicitly mapping IDs and intents.
Treat RNG parity as its own test suite. Lagavulin, Guardian, card choices,
relics, and other unsupported interactions remain outside this initial audit.

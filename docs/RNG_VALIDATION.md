# RNG reference validation

`cargo test --locked` compares Rust with 1,283 committed cases in
`tests/fixtures/java_rng.tsv`. The values were generated by compiling the local
decompiled libGDX `RandomXS128.java` unchanged, then executing it and JDK
`Collections.shuffle` with the project-owned driver `tools/RngOracle.java`.
No game source is included in the repository.

The companion `java_rng.json` records source SHA-256 hashes, fixture hash, JDK
version and scope. These identify the reference files used; they do not identify
the original game release or authenticate the decompiler's output.

## What is checked

- Seven seeds: 0, 1, 42, -1, signed-long minimum/maximum, and 123456789.
  TSV seeds/long results use unsigned decimal to preserve their 64-bit patterns.
- Mixed sequences of inclusive integer/range calls, booleans, probability
  checks, float bit patterns and long results. Integer bounds include zero,
  one, 99, and the largest valid inclusive Java int bound.
- A deliberately constructed RNG state that forces bounded sampling to reject
  its first raw result; the next output and wrapper counter are also checked.
- Shuffles of 0, 1, 2, 5, 10, 17 and 100 unique markers. Both initial deck order
  and draws after discard reshuffling are checked, along with RNG call counts.

The game wrapper's inclusive bounds and counter increments are mapped in the
driver from `cardcrawl/random/Random.java`; that wrapper itself is not compiled.
`CardGroup.shuffle()` seeds a fresh `java.util.Random` with one game RNG long,
then uses `Collections.shuffle`. Java draws from the end of its list; Rust
stores the next card at index zero. The driver reverses the shuffled list to
compare that representation. `CardGroup.initializeDeck()`,
`EmptyDeckShuffleAction` and `Soul.shuffle()` support this mapping by inspection.

`AbstractDungeon.generateSeeds()` and floor transitions establish that combat
streams use the same seed independently. Rust now accepts the effective combat
seed (run seed + floor in the game), rather than inventing per-stream offsets.
The simulator has no full-run state; relic/potion streams are placeholders,
not a reproduction of their history across floors.

## Regenerate locally

Requires the ignored reference sources and a JDK 16+ (`Stream.toList()` is used
by the driver). Normal Rust/Python tests and CI only read the committed fixture;
they do not need Java or decompiled sources.

```bash
.venv/bin/python tools/generate_rng_fixtures.py
# Or select an existing JDK explicitly:
.venv/bin/python tools/generate_rng_fixtures.py --java-home /path/to/jdk
git diff -- tests/fixtures
```

The generator also accepts `JAVA_HOME`. It compiles in a temporary directory and
does not modify reference sources. Review changed source hashes and expected
values before accepting regenerated fixtures.

## Limits and next work

Fixture agreement validates these inputs and algorithms, not whole-game parity.
The JDK version is recorded; this is not execution inside the game's shipped
JVM. The subsequent [constructor audit](ELITE_BOSS_AUDIT.md) checks fixed versus
rolled HP and corrects the order of pre-battle calls. Other effect call order,
monster AI, generated-card insertion and selected-card mechanics still need
audits and controlled combat traces. Record the original JAR checksum and build
when available. Seeded outcomes from earlier revisions are not directly
comparable; the current interface is v5 (242 observations / 73 actions). The first
[original-bytecode action traces](COMBAT_TRACES.md) now check card/shuffle RNG
counters across controlled card sequences; whole-combat RNG parity remains open.
